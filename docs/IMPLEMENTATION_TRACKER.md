## 축소 QA 원칙 (2026-10-12 사용자 요청)

- 단위별 Unity 컴파일 오류 0개와 핵심 동작 1회 확인만 우선 진행한다.
- 반복 정적 QA 전수검사, 매 단위 Windows 빌드/2클라이언트 검증 및 성능 검사는 실시하지 않는다.
- 종합 다인 연결, 레이턴시, 최대8인/NPC64 성능은 통합 개발 이후 한번에 검증한다.

- Unity 에디터는 사용자 지시대로 임의 종료/재시작하지 않는다.

## 단계별 보고 계약

하나의 기능 단위를 마칠 때마다: (1) 이번 구현 범위와 대응 Part/QA ID, (2) 실제 수정 파일,
(3) Unity 컴파일·Play·멀티 인스턴스 검증 결과를 서로 구분, (4) 미완료/버그/임시값, (5) 다음 단위.

**단위 '완료' 판정:** 코드 작성만으로 완료라고 표시하지 않는다. 에디터 컴파일과 해당 QA 시나리오를
실행했을 때만 동작 검증 완료를 표시한다. 외부 Cloud/2인 환경 등으로 확인 불가능하면 `검증 대기`로 표기.

## 문서와 달리 임의 확정하면 안 되는 사항

- 닉네임 제한 길이 및 중복 정책: 원문 P08-08에서는 추후 결정. 현재 코드 20자 제한은 임시 구현값이며 승인 전 확정으로 표시 금지.
- 모든 참가자/Host의 실제 Ping: 추정값이나 가짜 ms 표시 금지. 측정 불가면 -- ms로 표시.
- 카운트다운 마우스 시점, 만탄 접촉 시 아이템 소비 여부 등은 추후 확정. 구현 임시 처리는 테스트 후 보고.
- Owner 즉시 이동은 P10-10에서 실측 전 구현 권장. Host 최종 히트 검증과 일관성 검사 필수.
- 플레이어·NPC 공용 실제 Animator, Kyle 손총/1인칭 스킨드 팔은 아직 시각/런타임 미검증.
- GameScene 기존 베이크 성공은 경사로·옥상 접근 가능성 테스트 완료와 동등하지 않음.
