# 스테이지 맵 — 2026-10-16

GameScene에 기존 도시와 신규 맵 두 개를 저장했다. 로비의 플레이 흐름은 동일하며 매 스테이지(라운드 준비)마다 호스트가 세 맵 중 하나를 독립적으로 1/3 확률로 선택한다. 같은 맵이 연속으로 나올 수 있다. 재경기 투표로 다음 스테이지를 준비할 때도 새로 추첨한다. 플레이어용 맵 선택 UI는 없다.

| ID | 맵 | GameScene 루트 |
|---|---|---|
| 0 | 기존 도시 | CityWorld_72x72_PrototypeLayout |
| 1 | 도시 순환도로 | StageMap_01_IndustrialRing |
| 2 | 화성 전초기지 | StageMap_02_MarsOutpost |

기존 도시의 오브젝트를 재생성하지 않고 기존 루트를 그대로 사용한다. 신규 맵은 72×72m, 각각 스폰 9곳과 공용 아이템 후보 16곳을 가진다. 신규 맵의 MapAnchors 자식에서 좌표를 편집할 수 있다. 스폰 후보 전체 추첨/정렬은 기존 SpawnPointRegistry를 유지하고 지도별 앵커 소스만 전환한다.

도시 순환도로는 대형 산업 건물 복합체, 지상 순환도로, +4m 외곽 도로와 4개 진입 경사로, +1.2m 작업대 두 개로 구성했다. 화성 전초기지는 +3m 북쪽 로켓 기지, 서쪽 격납고, 동쪽 연구동, -1.5m 채굴장, +2m 착륙장, 통신소와 배경 모노레일로 구성했다. Space Kit의 색상별 원본 재질을 URP 재질로 옮겼다. 실내/중앙 건물 옥상/모노레일은 보행 영역에 포함하지 않았다.

StageMapDirector가 호스트의 선택과 클라이언트 준비 확인을 담당한다. 호스트는 이전 NPC와 아이템을 정리하고 지형을 적용한 뒤 선택 메시지를 전송한다. 해당 스테이지 참가자들의 준비 응답이 도착하면 캐릭터를 재배치하고 NPC를 생성하며 5초 카운트다운을 시작한다. 선택 메시지는 주기적으로 재전송하여 로딩 중 놓친 클라이언트에도 전달한다. 늦은 입장자는 현재 맵을 적용하고 관전하며, 스테이지 준비 시작 후 입장했다면 다음 스테이지부터 참가한다. 준비 응답이 30초 내 도착하지 않으면 라운드를 활성화하지 않고 로비로 돌아간다.

지도별 NavMeshData와 경사로 Mesh, 재질은 Assets/HideAndShoot/Maps/Generated에 저장했다. 지형과 경사로는 연속 충돌면을 사용하고, 건물·화물·암석 지붕은 NavMesh의 Not Walkable 영역으로 처리했다. 기존 도시에 있는 의도된 옥상 동선은 기존 데이터를 그대로 사용한다.

검증 결과는 AgentReports/StageMaps_2026-10-16에 있다.

- 공식 Unity CLI를 통해 에디터의 컴파일을 확인했다. 게임 코드 컴파일 오류/경고 0건.
- 세 맵 모두 스폰 9곳·아이템 후보 16곳의 NavMesh 위치와 상호 연결, 스폰의 캐릭터 캡슐 충돌 검사를 통과했다.
- 신규 경사로 12개의 오르기/내리기 총 24회 CharacterController 보행 검사를 통과했다. 실제 보행에서 발견된 화성 동쪽 경사로 출구의 암석을 이동한 최종 결과다.
- 로컬 NGO 호스트에서 각 맵에 2인 설정 NPC 30명과 8인 설정 NPC 72명을 생성하고 이동을 관찰했다. NavMesh에서 이탈한 NPC는 0명이다. 이는 외부 플레이어 2명/8명을 연결했다는 뜻이 아니다.
- 탄약/탐지 아이템의 시작 시 0개 상태, 시간 경과 후 생성, NavMesh 바닥 위 배치를 확인했다. 최종 측정은 탄약 2개, 탐지 1개, 지형에 묻힌 아이템 0개다.
- 스테이지 선택의 중복 실행 방지와 세 맵 선택을 Play 모드에서 확인했다. 독립 추첨 6,000회 참고 검사는 [1920,1989,2091]이며 연속 같은 맵도 허용됐다.
- 최종 PlayAudit.json의 passed=true, runtimeErrors=[]다. 외부 클라이언트를 실제 연결한 준비 응답/늦은 입장 검증은 수행하지 않았다.

제작 전 씬은 AgentBackups/StageMaps_2026-10-16/GameScene.before.unity에 보관했다. 최종 경사로 수정 전 에디터에 남아 있던 미저장 씬 상태도 GameScene.unsaved-before-exit-fix.unity로 보존했다. Play 검증을 마친 에디터는 편집 모드의 MenuLobbyScene으로 복원했다.

제작/검증 재실행 코드는 AgentScripts/BuildStageMaps.cs, AuditStageMaps.cs, PlayStageMaps.cs다. 이 파일들은 Assets 밖에 있으며 플레이어 빌드에는 들어가지 않는다. run_script로 BuildStageMaps를 컴파일하기 전 eval에서 System.Reflection.Assembly.Load("System.IO.Compression")을 호출해야 한다. Build()는 신규 맵 루트를 다시 만드는 명령이므로 손으로 수정한 신규 맵이 있으면 먼저 보존해야 한다. 일상적인 편집은 씬의 기존 오브젝트를 직접 수정한다.
